# Bookit — Decision Log

A running record of notable product and technical decisions. Add a new row each time a
decision is made. Newest at the top.

Template: `date | decision | why`

| Date | Decision | Why |
|------|----------|-----|
| 2026-10-17 | **NOVA REDESIGN v3 (new brand identity)**: this cancels all earlier Nova accent/type/icon choices. (1) **Ink is the primary action colour** (`primary` = `#111315` light / `#F4F5F7` dark, with `onPrimary` ink text in dark) — green is demoted to success/live/logo only (`success`/`brandGreen`); (2) **Bricolage Grotesque** (headings) + **Plus Jakarta Sans** (body) replace Inter/Inter Tight/Sora; (3) **phosphor-react-native** replaces lucide (uninstalled) behind the same single `<Icon>` wrapper, weight `bold`/`fill`, sizes 16/20/24; (4) **Microsoft Fluent Emoji 3D** PNGs (`src/assets/3d`, MIT) replace all hand-drawn SVG illustrations/category glyphs via `CategoryIcon`/`Illustration*`/`Fluent3D`; (5) app icon/adaptive/splash rebuilt on ink `#111315` with the green-tick mark. | Gives Bookit its own identity (no purple, no borrowed icon/illustration set) while keeping every feature, store, route, mock and i18n key. Because colour flows through `useTokens()`, type through `font`, icons through `<Icon>` and illustrations through `CategoryIcon`/`Illustration*`, each swap re-skins the whole app from one place. |
| 2026-10-17 | `check:design` now scans the **whole** `app/` + `src/` tree (no ratchet) and additionally fails on any banned legacy **purple/indigo/cyan** literal (`#6D5BFF`, `#8B7DFF`, `#4F46E5`, `#06B6D4`, …) anywhere, and on any direct `phosphor-react-native` / `lucide` / `@expo/vector-icons` import outside the `<Icon>` wrapper. | Makes "no purple except the Wellness tint" and "Phosphor only, via the wrapper" machine-enforced, not a review promise. The only purple left is the Wellness category tint `#F0EBFF`/`#211B33`, which is not in the banned set. |
| 2026-10-17 | **Originality rules — per-screen record.** No borrowed signatures are used (no yellow/green header band, no "<app> in X minutes" headline, no outlined ADD-over-image buttons, no left sub-category rail, no full-width green cart bar, no faded slogan footer, no other app's colours/icons/copy). Bookit signatures used instead, per screen: **Home** — green-tick logo in header, ink BookingBar with "Pick a time", colourful "Today's picks" bento, round ink "+" growing into steppers, LiveChip; **Category** — tint hero + 3D icon, sticky scroll-spy sub-category chips, Packages first, 2-col ServiceCards with ink "+", BookingBar; **Provider** — ink Book bar, sky verified tick, sunshine rating; **Checkout** — ink slide-to-confirm, green confetti success (3D party popper); **Account** — coloured `IconChip` rows (own category/role tints, no two adjacent the same); **Status/empty** — Fluent 3D illustration on a role tint. All actions are ink; colour comes only from content (category tints, bento, offers, 3D art, status). | The spec requires Bookit not to resemble any other app and to record compliance per screen; this row is that record. |
| 2026-10-15 | **NOVA redesign**: the theme is rebuilt on flat semantic tokens (`bg/surface/text/primary/accent/…`) as the single source of truth, read by new code via `useTokens()`; the legacy nested `Palette` is *derived* from those tokens and kept so all 57 pre-NOVA screens re-skin at once via `useColors()` without edits. | Lets a full visual rebrand (neutral surfaces + one accent, Aurora removed) ship instantly across every screen while the IA/component migration proceeds screen-by-screen, keeping every gate green at each commit. |
| 2026-10-15 | Brand is a geometric lowercase "b" mark (stem + checked bowl) + "bookit" wordmark in `src/brand`; app icon / adaptive (foreground + monochrome) / splash / favicon are rendered by a dev-only `scripts/generate-brand-assets.mjs` (sharp), never imported by the app. | One source SVG → all raster targets, reproducible, and the generator stays out of the runtime bundle (Expo Go safe). |
| 2026-10-15 | One `<Icon>` wrapper over a curated `lucide-react-native` registry (stroke 1.75, sizes 16/20/24); `@expo/vector-icons` is to be removed as screens migrate. | Single icon system, consistent weight/size, tree-shaken registry, and the only file allowed to import the icon lib. |
| 2026-10-15 | `check:design` (`scripts/check-design.mjs`, wired into `npm run lint`) enforces NOVA rules on a *ratchet* — the migrated surface (ui/brand/icons/features + migrated screens) — and grows file-by-file. | Makes the design lint real and zero-violation today without blocking on migrating all 57 legacy screens at once; the ratchet documents remaining work. |
| 2026-10-15 | Motion tokens live in `src/theme/motion.ts` and the signature easing is built lazily (`getEasing()`), so the theme barrel never imports `react-native-reanimated` at module load. | Keeps the token system usable in plain Jest unit tests (reanimated/worklets fail to init under Jest on import). |
| 2026-10-15 | `textSubtle` (#9898A3 light) is exempt from the enforced 4.5:1 contrast test; the test enforces 4.5:1 on `text`/`textMuted` vs every surface and `onPrimary` vs `primary`, and 3:1 on status/graphical colours. | A truly subtle placeholder tone can't meet 4.5:1 while still reading as subtle; WCAG exempts incidental/placeholder text, so enforcing it on essential pairs is the correct, honest bar. |
| 2026-10-13 | Maps are rendered as styled SVG placeholders (`MapPlaceholder`) and live tracking as an animated marker eased along an SVG polyline (`RouteMapTracker`, reanimated), never `react-native-maps`. | Keeps the whole app installable in Expo Go with no native map module while still demoing map toggles, address pins and live ETA tracking. |
| 2026-10-13 | All charts are hand-drawn with `react-native-svg` (`BarChart`) — no charting library. | One less dependency, full control over the Aurora gradient styling, and guaranteed Expo Go compatibility for the wallet, dashboard and earnings screens. |
| 2026-10-13 | Provider mode, chat, wallet, Bookit Plus, security (PIN/biometric), trust & safety and tickets are all mock-backed session-only Zustand stores. | Exercises real multi-screen flows and state without a backend or persistence, matching the existing demo architecture and Expo Go constraint. |
| 2026-10-13 | `moti` (pure-JS on reanimated) is used for micro-interactions (shimmer, heart pop, reveals, typing dots); widely-unit-tested primitives (e.g. `Input`) use the core `Animated` API to avoid loading reanimated's worklets under Jest. | Gives polished motion everywhere while keeping the test suite green, since importing `react-native-reanimated` directly into a Jest-rendered component fails to init worklets. |
| 2026-10-13 | UI language stays decoupled from region (English default, language chosen in Settings); currency still follows region via `useMoney()`. | Preserves the earlier decoupling decision across the full-app build so region changes money/format without forcing a language. |
| 2026-10-09 | Phone validation uses `libphonenumber-js` and accepts a number when valid and either mobile-typed or of unknown type (rejecting only known non-mobile types). | India (and some others) report no type for valid mobiles, so a strict "must be MOBILE" check would wrongly reject them; rejecting only known landlines keeps GB/IN/US all working. |
| 2026-10-09 | Dark-mode preference is a `'system' \| 'light' \| 'dark'` store resolved inside `useColors()`/`useColorSchemeName()`, overriding the OS scheme. | Keeps a single source of truth for colours and lets every existing screen honour a user override with no per-screen changes. |
| 2026-10-09 | All new features are mock-backed with session-only Zustand stores (no persistence, no MMKV in the runtime graph). | Keeps the demo fully Expo Go compatible and avoids native dependencies while still exercising real UI state and flows. |
| 2026-10-09 | Standardised on `@shopify/flash-list` for every list and `expo-image` (placeholder + `cachePolicy`) for every image. | Consistent performance and caching across the app, and a single pattern for contributors to follow. |
| 2026-10-06 | Provider response window for `requested` bookings is 15 minutes; after this the system auto-declines. | Keeps customers from waiting indefinitely and protects marketplace liquidity; short enough to retry with another provider quickly. |
| 2026-10-06 | No cancellation allowed once a booking is `in_progress`; it can only move to `completed`. Disputes are deferred to v2. | A service that has started should be seen through or resolved by a person, not cancelled by either party mid-job; dispute handling is v2 scope. |
| 2026-10-06 | `requested → declined` is a single transition for both provider decline and system timeout, distinguished by a `reason` column (`provider_declined` \| `timeout`) on `booking_events`. | Avoids a duplicate state/transition while still letting analytics tell the two causes apart. |
